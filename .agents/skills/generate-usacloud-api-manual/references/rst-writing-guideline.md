# reStructuredText チュートリアル作成ガイドライン

`usacloud` は Go プロジェクトであり、reStructuredText（reST/.rst）に慣れている開発者が限定的です。
このガイドラインは、`generate-usacloud-api-manual` スキルで生成するチュートリアルの体裁を統一し、
Sphinx などのドキュメントビルドで正しくレンダリングされることを目指します。

## 基本構造

```rst
================================================================================
タイトル
================================================================================

概要段落。

.. warning::

   注意事項。

セクション見出し
================================================================================

本文。

.. code-block:: shell

   usacloud <service>-api <resource> create --name example -y
```

## セクションの記法

上から順に以下の装飾を使います。装飾文字は見出し文字列より長くても構いません。

| レベル | 装飾 | 用途 |
| --- | --- | --- |
| 1 | `=` の上線と下線 | ページタイトル |
| 2 | `=` の下線のみ | 大セクション（Step 1 など） |
| 3 | `-` の下線のみ | 小セクション |
| 4 | `~` の下線のみ | さらに細かいセクション |

## 必須ディレクティブ

### 警告ブロック

本番環境でリソースを作成するチュートリアルでは、ファイルの冒頭に
`.. warning::` を入れ、profile 確認と承認を促します。

```rst
.. warning::

   このチュートリアルでは本番環境にリソースを作成します。
   作業前に ``usacloud config current`` で profile を確認し、
   対象プロファイルでのリソース作成を承認してください。
```

### コードブロック

シェルコマンドは必ず `.. code-block:: shell` で囲みます。

```rst
.. code-block:: shell

   usacloud eventbus-api process-configuration create \
     --name queue-job \
     --settings '{"Destination":"simplemq","Parameters":"{\"queue_name\":\"my-queue\"}"}' \
     -y
```

- 1 行が長くなる場合は末尾に `\` を入れて改行します。
- JSON 内のクォートはシェルで解釈されないよう注意してください。
- ファイルから JSON を読み込む例も併記すると、読者が編集しやすくなります。

### 補足ブロック

補足やヒントには `.. note::` を使います。

```rst
.. note::

   ``--quiet`` を付けると、作成されたリソースの ID のみが出力されます。
```

## 表現の指針

- **簡潔に**: 「どういうときに便利か」を 1〜2 段落で説明します。
- **具体的に**: コマンド例はコピー＆ペーストできる形にします。固定 ID は使わず、プレースホルダーと取得方法を示します。
- **順序を明確に**: resource の作成順と削除順を箇条書きで示します。
- **一次資料へのリンク**: ページ末尾に公式マニュアルの URL を必ず記載します。
- **``.rst`` 内のコマンド名は `./` を付けない**: チュートリアル本文では ``usacloud eventbus-api ...`` と書きます。

## 機密情報と実環境依存値の扱い

チュートリアルに掲載する例は、本番検証で実際に使った値をそのまま含めてはいけません。
以下は伏せるか、ダミー値・プレースホルダーに置換してください。

- API トークン、API シークレット、サービスプリンシパルの鍵などのクレデンシャル
- 実際の profile 名（``<your-profile>`` ではない具体的な名前）
- 実際のリソース ID（``<resource-id>`` ではない具体的な ID）
- アカウント ID、プロジェクト ID、その他の識別子
- 実際のログや API レスポンスに含まれる機密・識別情報

代わりに以下の表現を使います。

| 実際の値 | チュートリアルでの表現 |
| --- | --- |
| profile 名 | ``<your-profile>`` または ``your-profile`` |
| リソース ID | ``<process-configuration-id>`` など、リソースに応じたプレースホルダー |
| 取得した ID | シェル変数 ``${PC_ID}`` などで受け、後続コマンドで参照 |
| リソース名 | ``example-*`` や ``tutorial-*`` など汎用的な名前 |

レビュー時は、出力例に含まれる ID や profile 名が実際のものでないかを確認します。

## 本番環境での注意

- チュートリアルの冒頭に、profile 確認を促す警告を入れます。
- 作成後は必ず `list` または `read` で確認する手順を入れます。
- 最後に `delete` によるクリーンアップ手順を入れ、削除順の理由を簡潔に説明します。
- リソースが残ると課金が継続する可能性がある場合は `.. important::` で強調します。

## 根拠表との対応

チュートリアル内の各事実記述（サービス概要、制約、作成順など）は、
`generate-usacloud-api-command` の `references/help-and-service-model.md` に従って作成した
一時的な根拠表の行と対応させます。根拠がない説明はチュートリアルに含めません。
