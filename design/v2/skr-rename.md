# `skr` に改名する

## 背景

`usacloud` は長いため、頻繁に打つコマンド名としては少し不便。
短いコマンド名は、AI エージェントへの指示におけるトークン効率も良い。

今後、CLI のコマンド名は `skr` とする。

## 方針

- CLI のコマンド名は `skr` のみとする。
- レポジトリ名も skr に変更する
- 既存スクリプトは実行ファイル名を `usacloud` から `skr` へ変更する必要があるが、サブコマンドの仕様などは可能な限り維持されるので置換のみで対応可能とする。
    - **ここは議論の余地**
- `usacloud` という名前のコマンドは提供しない。
- `update-self` は `skr` を含むリリース資産を選択し、更新後も実行権限と設定を維持する。`usacloud` から `skr` への移行は自動的には行われない。
- ただし、コマンド体系（`server list`, `iaas server list` 等）は可能な限り維持する。
- 既存の `usacloud` ユーザーには、移行ガイドを提供する。
- 既存の認証情報やプロファイルを失わないよう、v1 の設定ファイルをそのまま読み込む。
- `SAKURA_*` / `SAKURACLOUD_*` 環境変数はそのまま維持する。
- 既存の `USACLOUD_*` 環境変数は少なくとも v2 系の間は互換入力として維持する。
    - 新しい `SKR_*` 名を導入する場合は `SKR_*` を優先し、対応する旧名が同時に指定された場合は競合を明示的にエラーまたは警告として通知する。
- 設定ファイルの保存先や環境変数を変更する場合は、移行コマンドまたは決定的なフォールバック順を別途定義する。暗黙に新規設定へ切り替えない。
